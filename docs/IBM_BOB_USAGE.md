# IBM Bob Usage — Phases 0–8

Full evidence behind the project's IBM Bob authorship claim, reconstructed
directly from git history and the actual GitHub PR pages (`gh` CLI wasn't
available locally, so PR bodies were fetched directly). This is the complete,
unbounded-length version — a trimmed statement for the actual hackathon
submission (word-limited) is a separate, later step from this document.

**Bottom line: IBM Bob built the project's foundation and all of Phases
0 through 8.** Claude's only footprint during that window was two
documentation/review PRs (#3, #5) with no engine code. The handoff to Claude
for all further authorship is itself a Bob-era artifact — PR #7, titled
"Bob is execution-only now," immediately follows PR #6 (Phase 8, Bob's last
authored PR).

## How this was verified

- **Git commit trailers** — checked every commit inside PRs #1–#7 for an
  author identity or `Co-Authored-By` trailer.
- **GitHub PR page bodies** — fetched directly (not visible from a local
  clone) for the actual "created with / generated by" footer text each
  platform appends.
- Claims below are marked **confirmed** (an explicit trailer or footer
  exists) or **inferred** (matches the content and LASTCONTEXT.md's session
  narrative, but the commit itself carries no explicit AI-tool trailer) —
  this distinction is kept deliberately, per this project's own standing
  rule to never claim something as measured/confirmed when it wasn't.

## The initial commit

`976d8ad`, "Initial commit: RepoGuard MCP Agent Guard project," pushed
directly to `main` before any PR-based workflow existed — 41 files, 2,582
lines, in one shot. It already contains the *entire* engine (`core.py`,
`api_check.py`, `visual.py`, `cli.py`, `pipeline.py`, `mcp_server.py`, the
web server), the full `demo-repo/` fixture, and the original `.bob/` config
(`custom_modes.yaml`, `mcp.json`, rules, skills) — this is where Phases 1,
2, 4, 5, 6 and the first drafts of 0, 7, 8 all originate. It carries no
explicit "Made with IBM Bob" trailer, but its scope and content match
LASTCONTEXT.md's own description of Session 1 exactly, and it is far too
complete to be a manual bootstrap.
